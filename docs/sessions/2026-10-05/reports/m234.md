## Live base and the edit

Live `mart.mart_daily_kpis` md5 `563f7c75de0a3ccd77a1bca45a52a4f5` = the 228 step 4 body, so 228 is deployed and is the base text. The 234 body (md5 `9dc5140218469a887bed32050d1bbf0e`) is the live text plus two edits, equal to the stored text of `mart_qa.m234_mart_daily_kpis`:

1. New CTE `client_cost_data AS (SELECT DISTINCT client_id FROM shop_daily WHERE cogs IS NOT NULL)`.
2. Final SELECT: `LEFT JOIN client_cost_data k ON k.client_id = COALESCE(s.client_id, p.client_id)` and
   `cm1/cm2/cm3 = IF(s.client_id IS NULL AND k.client_id IS NOT NULL, 0 / 0 - fulfilment / 0 - fulfilment - paid_spend, <existing expression>)`.

Design decisions:
- **Predicate is "no shop row" (`s.client_id IS NULL`), not "revenue NULL or 0".** Live dobias has 240 shop rows (2021-10 to 2022-05) with orders and cogs but NULL revenue and no spend. A revenue-based rule would turn those into 0 and break the dobias zero-diff. They stay NULL (separate data gap, not a zero-order day).
- **Cost data is per client, derived from the data** (a client has any non-NULL cogs shop day). Shopify and Shoptet always qualify (cogs coalesced or computed); Woo only once a line is costed (228). RawBark is NULL on every day today, so it is excluded; when its costs land the rule starts applying with no edit. No hardcoded client list.
- Only cm1, cm2, cm3 change, only on paid-only rows. revenue, cogs, orders and all other columns stay NULL there. Schema identical (34 columns, same names, order, types). No row fan-out (5364 rows both sides).
- A paid-only day with spend 0 (2 ethia days) becomes cm1/cm2/cm3 = 0, consistent with the rule.
