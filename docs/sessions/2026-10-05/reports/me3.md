- `6ed3d36` glue in 3 files OUTSIDE the list (see "Out-of-list edits"). It imports `toHitRateThresholds` / `referenceRate` / `HIT_RATE_REFERENCE_LABEL` from the main commit, so the two ship together; the glue commit alone does not compile on top of main.

## What changed, by change id
- **C2** `lib/creative/attribution.ts` (new): `ATTRIBUTION_LABEL = "Meta default attribution (per ad set)"`, the only place an attribution window is printed. `CreativeBar` uses it. ME2 flips this one constant. A check scans components, app and lib for "customers excluded".
- **C9** `classify(c, anchor, t, ageDays)` in `lib/creative/model.ts`: a would-be winner under `WINNER_MIN_AGE_DAYS = 14` returns `open`. Unknown age (no launch table) applies no rule. Every surface goes through it: `launchStatus` (tile, trend, Paid, Reports via `evaluate.ts` which already calls `launchStatus`), `winnerEconomics(ads, mean, t, ageOf)` (scorecard), `toAdView` (grid outcome), Production. Fixture: tile, grid and scorecard agree on every age x purchases x ROAS cell.
- **C3** one anchor: `AccountContext.anchorRoas` = stored 365-day `prior_roas` (new read `getLaunchAnchor`, also gives ad ages), used by scorecard, grid, Concepts, Breakdown, Production; `meanRoas` stays only for the Blended ROAS tile. Grid tile (`lib/creative/tone.ts`, `roasTone`): green only for `outcome === "winner"`, lighter "promising" tone for directional-and-above-target; AdDetail ROAS dot follows the same rule. Scorecard tile renamed "Winners with delivery in period". Production "Net-new hit rate" = `hitRate()` on the launch cohort restricted to the screen's net-new ads (same function as the tile), "Ads per winner" lost its "5%" text.
- **C4** `toHitRateThresholds()` in `store.ts` (target ROAS + read threshold only; kill and CPA read 0). Creative page, Paid tile and Reports route use it, so Venev gets a hit rate. `diagnose()` no longer says "Body problem" when Target CPA is 0. CPA currency: Settings form now takes the Meta ad account currency (`metaCurrency ?? currency`) for CPA, pack budget, per-ad floor, monthly budget, with a hint.
- **C5** `lib/creative/floors.ts` + `getVideoAdRates` (`lib/queries/creative.ts`): genuine video = video starts >= 30% of impressions and >= 5,000 impressions, trailing 180 days to the client's latest day, p25 of hook (3s plays / impr) and of hold (ThruPlays / impr), min 15 ads, else the stored Settings floors (default 20% / 5%). Applied to `thresholds` and `display` in `loadCreative`; `diagnose` text says "(your p25 of video ads)" for the relative one. Diagnostic only. Note: the 30% test is applied directly on window start share (same 30% as ME1's `is_video`), not through the table's `is_video`, so it does not depend on ME1's deploy and a video file that is rarely played as video does not enter the percentile.
- **C6** `LaunchData.refreshedAt` (`FORMAT_TIMESTAMP` of max `refreshed_at`), `updatedLabel()` ("Updated 10:10" today, "Updated 3 Oct 10:10" older, Prague time) shown in `CreativeBar` (tooltip "When the hit rate snapshot was last built"). `deltaWithheld(cur, prev)`: tile change suppressed when current has open launches and the comparison has none (same rule Reports uses).
- **C7** `launchContext()` (new ad set vs added to existing, `unknown` counted separately) and `packHitRate()` (ad sets whose first delivery is in range with at least one launched ad; a pack with a winner among its launched ads). `HitRateTrend` renders a small "Launch context" table under the chart; columns missing = one line "Launch context is not ready." `LAUNCH_SQL` now selects `r.*` so a table without the ad set columns still gives the hit rate.
- **C10** `HIT_RATE_REFERENCE` (5%) removed everywhere. `referenceRate()` = client's own hit rate over the 365 days to `through` (`referenceStart`), shown as dashed line "YOUR 12-MO RATE x%" on the trend, in the Creative and Paid tile info, and on the Production tile. Reports: the fixed reference is removed from `hit_rate` (no per-client reference there, see open points).
