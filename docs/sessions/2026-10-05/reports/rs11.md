## F1 (partial NULL sums)
Facts found in the view definition (`mart.mart_daily_kpis` is a FULL OUTER JOIN of shop and ad platforms):
- Shop columns are NULL on a day without orders (Manami: 3 such days). That is a real zero, not a gap.
- `paid_spend = COALESCE(meta,0) + COALESCE(google,0)` is NULL only when no ad-platform row exists for the day. That is the gap.

Implementation:
- Registry: new `ComponentDef.nullMeans: "gap" | "zero"`. Shop columns `zero`; `paid_spend`, `meta_*`, `google_*` `gap`; `cogs` `gap` but counted only on rows where revenue > 0; phase 2 campaign marts `zero` (live: 20 all-NULL email rows, 870 NULL add_to_cart, those are "nothing reported"). `SEMANTIC_VERSION` 1 to 2.
- Compiler (still one query per widget, identifiers still whitelisted): per component `COUNTIF(col IS NULL)`. Money: `<alias>__nat_nulls` (client-currency rows) and `<alias>__disp_nulls` (all rows). Other: `<alias>__nulls`. COGS: `... AND t.revenue > 0`. `run.ts` carries them as `ComponentSum.natNulls/dispNulls` (optional, absent = 0, so old rows and fixtures behave as before).
- Evaluator: counts are summed through bucket, total and rollup. A gap component with NULL rows makes every `nullAs: "gap"` term over it a gap, so the cell is `no_data` with reason "Missing days". Rollups: one client with a gap nulls the combined or vertical cell (same rule as fx_missing). COGS with any NULL row on a revenue day is `not_measured` ("No cost data"), also inside totals and rollups. Native-per-client ratios read the native count, display-currency money reads the display count.
- Precedence unchanged: not_connected > fx_missing > not_measured > no_data.
- Documented treatment of `nullAs: "zero"`: fulfilment and paid spend inside CM3/CM3 % still count NULL as 0 (owner decision, mart definition). Residual: for a connected client with missing ad days, CM3 is still overstated by the missing spend. Possible follow-up, not done.
- Meta columns for a Google-only client are not terms of MER, so they cannot null it (fixture test, and live data below). Meta-only metrics stay `not_connected` there; for a Meta client with NULL Meta days, only Meta metrics become gaps.

Checks added: `check-reports-eval.ts` section 4.12 (the review case [100, NULL] spend gives a gap instead of 20; week, day, total, comparison, per-client, combined, native vs display, shop zero, Google-only, Meta, CM3, COGS, legacy rows; 255 checks, 13 of the new ones fail on the old evaluator). `check-reports.ts`: SQL snapshots updated (design 2.8 text plus 3 hashes), new SQL, COGS-guard and normaliser assertions (297).
